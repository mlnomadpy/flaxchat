# Full system audit and tool decisions

Use this mode for an explicit full audit, issue review or training-tool/skill upgrade.
Read current source and durable receipts; do not allocate hardware merely to audit.

## Divide ownership and reconcile

When parallel agents are requested, assign training/data/recovery, infrastructure/
cost/lifecycle and evaluation/parity/release to separate reviewers. Each reports
concrete source evidence, implemented behavior, actual acceptance and one next
gate. Root owns shared docs, issue reconciliation and any campaign ledger.

Refresh every open GitHub issue including full bodies and comments. Check query
limits/pagination and timestamp the raw snapshot. Map every finding to its existing
tracker and remaining acceptance, including non-embedding release/decoder/demo
issues. Read all open issues before creating a duplicate. Judge closure against each original acceptance contract: do not silently add whole-production, multi-host or release gates to a narrow cursor, deduplication or tokenizer issue. Record implementation-complete/acceptance-passed/pending-integration separately. Put broader readiness work on its own existing tracker so individual fixes can finish. New uncovered defects
get concrete repro, scope and acceptance; preserve original issue bodies.
Read-only inspection is different from publishing internal cloud/data/cost details.
Retain a local payload when external posting is rejected; never bypass the rejection
by changing tools. No issue closes on docs or metadata fixtures alone.

## Maintain one current decision surface

Update the current system audit, every-issue checklist, training runbook and tool
inventory. Retain dated receipts and link them instead of accumulating conflicting
"latest" summaries. State the last durable trained checkpoint, failed/unrun physical
scopes and one immediate gate. Audit-only scope does not imply training restart,
publication, destructive cleanup or paid CI dispatch.

For an observer, retain the trusted canonical spec SHA outside the remote job and pass it explicitly. If unavailable, recover trusted admission evidence for the same handle; do not start a replacement. After an observer/controller change, preserve historical Linux passes under their old source hash and require changed-source lifecycle qualification.

## Select tools by the missing evidence

| Missing evidence | Existing preferred tool | Acceptance |
|---|---|---|
| Parent bytes/leaves | Generation-pinned GCS, enriched export, production-parent validator | Full original SHA/lineage, then all-leaf physical TPU import |
| Failed copy diagnosis | Bounded artifact-transfer diagnostic | Actual executor bytes/time/client receipt; a range is diagnostic only |
| Objective/cache correctness | Frozen physical pytest/JUnit and named boundary diagnostics | Original numerical tolerances, loss/gradient/Adam and recovery checks |
| Data/quality | Exposure/quarantine tools, native evaluator, pinned inventories | Actual independent multilingual/code coverage, parent baseline and regressions |
| Full-corpus retrieval | Bounded TPU corpus scoring and corpus/protocol identity | Actual encoder integration and complete traversal; scalar fixture/top-k list alone is insufficient |
| Efficiency | Global telemetry, short warmed JAX/XProf traces | Synchronized physical useful-exposure and whole-stage timing, HBM/RSS and overhead |
| Scaling/faults | Guarded supervisor, independent lease, multi-host/fault validators | Sustained intended topology, global negatives, exact resume and scoped cleanup |
| Model comparison/release | Matched receipts, isolated JAX/TorchXLA, pinned MTEB | Actual competitor adapter and scores, current full parity and immutable upload inventory |
| Dollars/storage | Provider rows/export, run labels, generation inventory | Posted costs separated from credits/reservations; live/versioned/soft-deleted retention |

Use the existing JAX/Flax/Optax/Orbax stack first. Do not install a replacement
platform to compensate for unexecuted correctness gates. A dashboard is optional.
Disk-backed preprocessing, FSDP, custom Pallas kernels, teachers, hard-negative
refresh and Matryoshka objectives require a measured bottleneck or quality deficit
and an isolated stage/equivalence check. Gradient accumulation does not enlarge
the simultaneous negative pool. Distinguish an implemented scorer from a physically
qualified end-to-end evaluator.

## Validate the upgrade

Run focused model-free checks for orchestration/metadata changes and inspect links
and skill schema. Preserve the user's TPU-only rule for model execution. Forward-test
a realistic audit/failed-worker/new-stage request with an independent reviewer when
parallel review is authorized. Update both versioned and installed skill copies;
report separately if installation is blocked.
