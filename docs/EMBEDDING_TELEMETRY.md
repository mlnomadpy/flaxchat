# Embedding training telemetry

`train_yat_embedding_finetune.py` emits actual global exposure at every accepted update, using an all-host metadata gather at a fixed cadence. Integer counts remain int32 through transport, independent of JAX x64 configuration, then are summed as host integers. Before the loop, every host rejects configurations whose maximum local token count cannot fit int32. The reduction handles different padding density across hosts.

`processed_tokens_global` counts query, positive and encoded hard-negative nonpadding tokens. `useful_tokens_global` excludes invalid hard-negative rows and the unused third encoder of a pair-only update. These are repeated valid input exposures, not deduplicated corpus tokens, unique examples or a measure of quality; objective-level duplicate masking may further reduce contributing negative candidates. Existing authenticated exposure and recovery state remain authoritative for replay and source/language coverage.

Step throughput uses summed exposure divided by the slowest host's elapsed input-and-update time. It includes first-call compilation but excludes the subsequent telemetry gather. `first_variant_call` labels the initial invocation of each static pair/triplet variant. `compile_and_first_update` combines compilation and execution; it is not an isolated compiler measurement.

The successful invocation summary reports setup, input, compile-and-first-update, steady updates, development evaluation, best checkpoint, recovery checkpoint and manager finalization separately. Whole-invocation throughput divides only this invocation's accepted useful exposure by its slowest-host wall time from `run()` entry through manager close. This includes setup, development probes, checkpointing and per-step metadata gathers. It excludes cloud provisioning, process startup before `run()`, the final summary gather and earlier invocations. A resumed invocation never claims lifetime throughput. Phase host maxima need not sum to the slowest host's wall time. `posted_cost_usd` stays null: neither a reservation nor an elapsed-time price estimate is billing evidence.

No telemetry counters enter recovery state or bypass exact-source identity checks. This code change changes source identity; old-stage exact resume must still reject mismatched source until an explicit migration/new-stage qualification is authorized. The optimizer, schedule, data replay and checkpoint-selection decisions are unchanged.

Validation: literal host-metadata tests cover uneven padding, invalid-negative exposure reduction inputs, large exact integer counts, first-call attribution, complete-stage overhead, zero-update resumes and failed-save timing. No CPU model execution is used. Physical acceptance is still required: run on one and multiple physical TPU hosts, compare counted tokens with authenticated data exposure, verify collective cadence during pair/triplet alternation, profile gather overhead, verify checkpoint/evaluation timing, and exercise a worker failure under the existing bounded controller. Local metadata tests do not qualify TPU behavior or performance.
