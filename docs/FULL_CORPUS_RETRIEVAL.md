# Reporting retrieval over the actual benchmark corpus

The existing `flaxchat.embedding_quality.retrieval_metrics` uses the selected development positives as its candidate pool. That is a cheap training probe, not an official full-corpus benchmark. Keep its checkpoint-selection behavior unchanged. Do not compare that probe's MRR with mmBERT or EmbeddingGemma results from a larger corpus.

`flaxchat.full_corpus_retrieval` and `scripts.report_full_corpus_retrieval.py` report native nDCG@k, MRR@k and Recall@k from already scored, authenticated ranking artifacts. They do not encode text or infer scores from JSON. Their reporting-only contract separately pins the complete corpus text snapshot, query text snapshot, qrels and rankings with actual byte counts and SHA256 hashes. The contract itself must match an independently retained SHA256 before any report is committed. Query/corpus/qrels identity is distinct from the scoring protocol and the model identity, allowing matched-query uncertainty without conflating models.

The protocol explicitly declares cutoffs, graded nDCG gain (`linear` or `exponential`), binary relevance above zero and descending-score/ascending-document-ID ties. Unknown or duplicated IDs, invalid judgments, nonfinite scores, inconsistent ranking order, incomplete query groups and exceeded row/deadline bounds fail. Every declared query must have a positive qrel; omitted relevant documents still count in the Recall denominator. This deliberately avoids silently filtering hard queries or treating one positive per query as the complete relevance set. Values remain native fractions; no percentage or arbitrary benchmark normalization is applied. Optional existing `bootstrap_query_mean` intervals are descriptive only, conditional on independent queries and fixed corpus/judgments/protocol.

Two input modes serve different purposes:

- `exhaustive`: each query must rank every authenticated corpus document exactly once. Useful for small independent fixtures and scorer parity. It verifies supplied candidate coverage, not encoder correctness or whether the pinned corpus is itself the official complete source.
- `topk_unqualified`: retains a declared depth covering every cutoff, authenticates all input artifacts and computes correct metrics against the full qrels denominator, but explicitly sets `full_search_qualified=false`. A bare producer assertion or top-k JSON cannot prove all documents were searched. This mode avoids requiring enormous query×corpus ranking artifacts for production corpora.

`flaxchat.full_corpus_tpu.score_tpu_blocks` is the scalable producer implementation awaiting physical qualification. It accepts already encoded TPU query embeddings and streamed document-embedding blocks, validates traversal against independently authenticated sorted complete corpus IDs, normalizes in FP32 and computes cosine scores on TPU in bounded query/document blocks. Only query×k candidate scores/indices remain on TPU; host storage is O(corpus document IDs + query×k), rather than a query×corpus score matrix. The final top-k output has explicit ties and a source-bound coverage receipt. There is no CPU fallback. The first implementation rejects multi-host execution explicitly. A deadline checked between blocks does not interrupt an already dispatched JAX kernel or blocking encoder generator: an independently enforced outer process/cloud lease remains mandatory.

The producer is not yet wired into the physical YAT encoder adapter, run on TPU or independently checked against an exhaustive oracle. Its receipts therefore state `producer_numerically_qualified=false` and `encoder_execution_verified=false`. Do not promote a top-k report to full-search qualification merely because a receipt says TPU. Required next steps are: authenticate official benchmark corpus/query/qrels splits and source revisions; stream tokenizer/encoder batches through the released YAT adapter with its prompts/pooling/truncation identity; verify block traversal and token exposure; test tied scores, last partial blocks, multiple query blocks and parity on physical TPU; then verify complete real-corpus execution and bind its producer/qualification receipts to the report. Official paper comparisons additionally require the same tasks, splits, retrieval cutoffs, qrels semantics and native scoring units. Metadata fixtures prove none of those model-performance claims.

The reporting contract format is `flaxchat-full-corpus-report-contract-v1`. It contains `purpose="reporting_only"`, `source_split`, explicit `source_identity` and `model_identity`, `ranking_mode`, optional `ranking_depth`, `protocol`, finite `max_rows`/`max_ids`, and a `files` mapping with exactly `corpus`, `queries`, `qrels`, `rankings`. Files are relative regular JSONL artifacts without symlinks: corpus/query rows use `id,text`; qrels use `query_id,document_id,relevance`; rankings use `query_id,document_id,score`. Corpus and query text snapshots establish byte identity but do not independently prove provider completeness or contamination freedom. Keep parent exposure, source licensing and benchmark split quarantine as separate gates.

```sh
python -m scripts.report_full_corpus_retrieval --contract report-contract.json --contract-sha256 <retained-SHA256> --output new-report.json
```

No training selector changes, model runs or cloud writes are performed by the reporter. The metadata suite uses hand-derived literal rankings and authenticated small text fixtures; it does not generate embeddings or claim TPU scorer validation.

## Frozen physical YAT encoder entry point

`scripts.evaluate_yat_full_corpus_tpu` now connects the existing released-parent loader and `ModernBert.pool` to the TPU block scorer. This implementation has not been run on TPU yet. It is a new execution path awaiting qualification, not evidence that a benchmark finished.

Metadata admission authenticates the complete JSONL snapshots before model construction, sorted unique corpus/query IDs, full qrels coverage, source repository/revision, every evaluator/model Python source, the enriched parent export and independently pinned parent artifact hashes. The physical branch refuses CPU and multi-host execution before importing the model. It verifies frozen Python/package versions, loads the unchanged YAT parent, checks every restored parameter leaf against its committed shape/dtype/byte hash, then tokenizes and pools on TPU. Bias 1, epsilon .01 and trainable alpha remain the trained configuration; architecture/runtime overrides are not accepted.

Batching follows the existing public adapter's power-of-two sequence buckets, fixed row capacity, right token-ID truncation, no prompts, nonpadding mean pooling including special tokens, and FP32 L2 cosine normalization. Queries are encoded once; documents stream through bounded encoder and scorer blocks. Exposure records separately count query/document texts, useful nonpadding tokens, padded processed tokens and truncated texts. The full corpus IDs and streamed bytes are checked, as are query snapshots and parent/source hashes after execution. The scorer rejects zero/nonfinite norms—including overflow from extreme finite vectors—and nonfinite retained scores rather than silently converting them into zero embeddings.

The input format is `flaxchat-yat-full-corpus-tpu-v1`. Besides the shared source/protocol/file pins, declare `corpus_scope="full_source_corpus"`, `purpose="reporting_only"`, exact parent step/manifest/metadata/leaves/artifact hashes, `source_files_sha256`, Python and package runtime pins, sequence length, encoder/document/query block sizes, top-k, finite document/query/qrels bounds and an execution deadline. Query count is strictly below 10,000. Admission requires explicit retained top-k TPU bytes and estimated host-result bytes budgets; those estimates do not certify total peak TPU/host memory or compensate for model/context memory. Supply `max_retained_topk_bytes` and `max_host_results_bytes`. Use `--print-source-inventory` to collect current source hashes, freeze them independently, then run metadata admission before allocating hardware. The physical output directory must be fresh and on the same filesystem as snapshot files because the reporter uses regular hard links rather than copying multi-GB corpus bytes or trusting symlinks.

```sh
python -m scripts.evaluate_yat_full_corpus_tpu --contract physical-contract.json --contract-sha256 <retained-SHA256> --metadata-only
python -m scripts.evaluate_yat_full_corpus_tpu --contract physical-contract.json --contract-sha256 <retained-SHA256> --output /tmp/fresh-yat-retrieval-output
```

The worker writes incremental `progress.json`, terminal status, source-bound `producer.json`, top-k rankings, a pinned metric-report contract and the native report. Completed execution remains marked `completed-physically-unqualified`, and numerical qualification remains false. Full-search/model-quality acceptance cannot be obtained by changing those booleans: independent physical scorer parity, released-parent encoder parity and faithful complete benchmark corpus/protocol evidence are still required. Upload only needed reports/rankings/receipts through the separately bounded cloud controller; scratch corpus hard links are not a request to publish the dataset.

The new explicit physical test module is `tests/test_full_corpus_retrieval_physical_tpu.py`. Enable it only inside a frozen, guarded physical TPU campaign with `FLAXCHAT_RUN_PHYSICAL_FULL_CORPUS=1`; it refuses CPU fallback. It covers tied cosine scores with lexically ordered document IDs, multiple query blocks, a final partial document block, single-block versus streamed-block parity, missing/foreign corpus IDs, zero vectors, NaN/infinity and finite values whose FP32 norms overflow. These tests have been written but not executed. They test the scorer, not the actual trained-parent encoder. The next bounded campaign must additionally check tokenization/truncation parity against the existing public adapter and run a small real complete benchmark corpus with the authenticated actual parent before a large corpus run. No automatic selection-policy change follows either test.

### Review corrections before physical acceptance

The integration now admits a separate `max_host_working_bytes` budget and `max_document_block_host_bytes` (at most 256 MiB). It checks the host estimate incrementally while retaining corpus/query IDs and judgments, includes retained reports and a conservative parent-weight allowance, and checks actual Linux `MemAvailable` before parameter construction. This remains an estimate, not measured peak-memory qualification. Document batches obey both row count and actual Python text-memory bounds; one exceptionally large row fails instead of accumulating an oversized block. Physical snapshots must contain exactly `id,text`, so source-specific title/text concatenation must happen explicitly in the pinned snapshot preparation rather than being silently omitted by the encoder.

The scorer reuses independently authenticated document ID strings, validates final retained index bounds and uniqueness, and pads document compute blocks to the declared capacity with masked scores. This preserves the real corpus count and tie semantics while avoiding a separate main score/merge compilation for each varying text-limited chunk length. Numerical correctness of that masked path still needs the physical oracle cases. The metric reporter correctly allows cutoffs above the complete corpus size: a three-document corpus can report Recall@10 with only three retained documents, while still requiring all available documents when that is the scoring depth.

Remaining concrete blockers before TPU acceptance are the unexecuted scorer oracle, trained-parent pooling/tokenization parity, measured host/TPU peak memory under the chosen context and batch sizes, and a real complete-corpus run bound to official snapshot/protocol identities. No metadata assertion or source receipt proves those requirements.
