# Evaluation and PyTorch release qualification

New evaluation receipts use the model-free [evaluation contract](../scripts/evaluation_contract.py). Each frozen task inventory contains task/category/immutable40-character revision, exact split/subset pairs, `main_score` and the named `finite-main-score/row-macro/task-macro/category-macro-v1` aggregation policy. Empty, nonfinite, duplicate, unknown and missing rows are rejected. A selected-task shard may be `selected_complete` while remaining incomplete as a full benchmark. The evaluator validates resumed receipts before loading the model and validates each task before accepting it. Merge and assembly revalidate row coverage rather than trusting a cached `complete` flag.

The protocol identity records model file hashes, source hashes including evaluator/loader/kernel and split/subset helpers, the installed package inventory, device kinds/process topology, batch size, lengths/padding, pooling and prompts. Changed identities invalidate exact resume. Interpreter/build hashes, numerical environment/effective JAX configuration and available guarded runtime/deployment receipts also enter the identity. Floating registry revisions are resolved to immutable dataset commits before loading; internally inconsistent declared row products are rejected. New runs freeze their inventory on first write; cross-run comparisons require the exact same inventory and protocol. Existing historical receipts missing row inventories are not silently upgraded from observed scores. Preserve them as historical evidence; obtain an independently pinned expected inventory before migration or run fresh physical TPU evaluation.

For generic assembly, pass `--suite-inputs` to [the assembler](../scripts/assemble_yat_embedding_full_mteb.py): a JSON object mapping suite names to arrays of receipt paths. Suite completeness derives from frozen inventories. The original `--root` historical layout remains specifically labelled as the 41-English/131-multilingual run arrangement. Its eight-common-category mean remains a separately named paper comparison; it is not the native nine-category multilingual mean.

Portable exports now preserve authenticated committed checkpoint metadata/manifests and artifact hashes. New committed embedding stages and architecture-derived tensor counts are supported; publishing requires an explicit fresh `--repo`. Legacy exports lacking preserved lineage must be regenerated from the durable checkpoint. PyTorch conversions now emit `flaxchat-yat-pytorch-v2` receipts binding weights, config, tokenizer and shipped implementation. Parity output sidecars bind the actual fixture, output, source/target artifact files, source code, runtime and device evidence. Comparison requires matching inputs and batch protocol. Publication rejects legacy/unbound receipts, stale artifacts and every absent/nonfinite numerical gate before creating a public repository. After upload it verifies every required remote file at the returned immutable revision, including config and implementation.

Use [run_yat_parity_case.py](../scripts/run_yat_parity_case.py) on the admitted TPU worker to run a single length/batch case with required `--source`, `--target`, `--jax-python`, `--torch-python`, `--evidence`, `--length` and `--batch-size`. `--timeout-seconds` is bounded between60 and1800 seconds and applies to the entire case; durable status receipts preserve failures. Completed cases are merged with the parity tool's `matrix` subcommand. A single successful case never qualifies the full matrix.

The suite runner supports `--module-timeout-seconds` within `--timeout-seconds` minus a65-second evidence margin (default module240 seconds). Declare larger budgets explicitly for training acceptance; expensive parity cases should be scheduled independently rather than assuming the whole matrix fits one module.

The [physical acceptance module](../tests/test_torch_parity_tpu.py) uses separate JAX and TorchXLA subprocess environments. Configure `YAT_PARITY_SOURCE`, `YAT_PARITY_TARGET`, `YAT_JAX_PYTHON`, `YAT_TORCH_PYTHON` and a durable `YAT_PARITY_EVIDENCE` directory. It runs lengths 128/256/512 and the advertised maximum, with inference batches 1/8. Fixtures cover multilingual text, code, long/truncated documents, empty strings and an all-padding row. Eight queries rank a separate 64-document corpus. Layer outputs, pooled vectors and rankings are compared. Published matrix gates require intermediate-layer cosine at least 0.99, minimum pooled cosine 0.9998, exact top-1/top-3-set agreement and at most 0.01 cosine-score drift. These are declared release tolerances, not proof of full benchmark equivalence or serving speed.

No new physical TPU parity has been executed for these changes. Missing physical environments/artifacts/durable evidence are explicit skips. Zero-mask mismatches, collapsed embeddings and fixture-shape mismatches now fail before comparison. Model-free receipt tests pass independently of model runtime; they do not qualify numerical behavior, performance or long-context TPU memory capacity. The 64-document fixture is an implementation smoke corpus, not a representative production retrieval benchmark. Run the full pinned candidate/baseline retrieval evaluation separately before production quality claims.

## October 1 parity campaign upgrade

New parity receipts are `yat-release-parity-v3`; legacy narrow receipts remain historical. Intermediate output names are derived from positive `num_hidden_layers`: layer 0 and layer `(depth - 1) // 2`, deduplicated for shallow models. The versioned `first-and-middle-layer-v1` policy, depth and indices are bound into every case scope and checked against the released config. Both backend receipts retain package inventory, interpreter/build/executable identity, numerical environment, effective JAX and Torch settings, and all three guarded deployment receipts. Set `FLAXCHAT_RUN_ROOT` to the independently admitted worker root containing `manifest-identity.txt`, `runtime-receipt.json` and `hardware-receipt.json`; absent deployment identity now fails before model loading.

Use [run_yat_parity_campaign.py](../scripts/run_yat_parity_campaign.py) to schedule cases independently. Required arguments are `--source`, `--target`, `--jax-python`, `--torch-python` and `--evidence`; defaults bound the campaign to1700 seconds, each case to1200 seconds, and new work to one case. Every invocation probes current backend numerical/source/model identity without constructing a model, rejects changed campaign identity, verifies existing reports and raw output/fixture hashes, then executes only missing cases. `campaign-summary.json` explicitly distinguishes partial progress from full qualification; CLI exit2 means partial, not passed. Rerun the same identity under another independently bounded lease to schedule missing cases. A changed identity needs a fresh evidence namespace. Failed cases do not erase successful cases.

The physical unittest now invokes that campaign rather than restarting the whole monolithic matrix. `YAT_PARITY_CAMPAIGN_SECONDS`, `YAT_PARITY_CASE_SECONDS` and `YAT_PARITY_MAX_CASES` optionally set its declared bounds. Partial progress intentionally does not pass full-matrix acceptance. Set the enclosing suite module timeout greater than the campaign budget plus interpreter startup/evidence margin, and keep that suite within its independently guarded cloud lease. Each maximum512 encoder has six cases: lengths128/256/512 × batches1/8. A larger advertised maximum adds two cases; these are numerical/memory acceptance, not proof of long-context quality.

The separate JAX runtime needs JAX/JAXlib, libtpu, Flax NNX, NumPy, Safetensors and tokenizer dependencies for the public loader. The Torch runtime needs mutually compatible torch/torch_xla TPU builds, NumPy, Safetensors and tokenizer dependencies. Resolve exact versions from the independently frozen backend locks; installing both runtimes into one environment is unsupported. The campaign itself constructs no model and allocates no hardware.

[validate_mteb_inventory.py](../scripts/validate_mteb_inventory.py) inspected actual installed MTEB2.21.8 task instances without loading datasets or constructing a model. The [metadata receipt](../tests/fixtures/mteb-2.21.8-task-metadata.json) confirms one STSBenchmark row,18 MIRACL hard-negative subset rows and six WebLINX split rows with immutable dataset revisions and actual task-source hashes. This clears the representative package metadata compatibility question. Actual dataset loading, emitted numerical result rows and physical evaluation remain unqualified.
