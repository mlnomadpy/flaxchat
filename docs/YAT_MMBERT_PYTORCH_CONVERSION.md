# YAT mmBERT step-12,000 PyTorch conversion

The native PyTorch release is [mlnomad/yat-mmbert-base-contrastive-12000-pytorch](https://huggingface.co/mlnomad/yat-mmbert-base-contrastive-12000-pytorch). It converts all 181 tensors from the [Flax/JAX checkpoint](https://huggingface.co/mlnomad/yat-mmbert-base-contrastive-12000), including trainable YAT FFN and attention alphas. Flax linear kernels are transposed to PyTorch layout. The embedding table and MLM-head tensors are retained, while the current inference API exposes encoding and pooling. The standalone implementation is in [`torch_port/yat_encoder.py`](../torch_port/yat_encoder.py).

Conversion and publication ran on a one-chip Spot v5e TPU VM in the billed `azettaai` project. The VM downloaded the Flax release directly from Hugging Face, avoiding a weight transfer through the local Mac. The published conversion receipt gives source SHA-256 `91908ea06c933966b954b0948a34042798395fdf865e1564c71cf82db5c37956` and PyTorch SHA-256 `21d8a9c3a4b80ba32960f3d7b171991a1c9b1e892fee2e4c577743beffa40f7c`; Hub LFS metadata independently matched the latter. The temporary upload token was deleted from the VM, and both the queued resource and VM were deleted after validation.

## Reproducible TPU parity procedure

1. On a TPU VM, run [`setup_yat_torch_tpu_vm.sh`](../scripts/setup_yat_torch_tpu_vm.sh) to create separate JAX and PyTorch/XLA environments. `torch_xla` needs the uv Python library path in `LD_LIBRARY_PATH`; [`run_yat_torch_tpu_stage.sh`](../scripts/run_yat_torch_tpu_stage.sh) sets it for every stage.
2. Download the Flax release from Hugging Face on the VM. Run `python -m torch_port.convert_yat_encoder SOURCE OUTPUT` in the PyTorch environment. The converter checks the source SHA-256, tokenizer, tensor count, names, shapes, and dtypes before writing the new safetensors file.
3. Run the `inputs`, `jax`, `torch`, and `compare` stages of the runner. Both forward passes refuse a non-TPU backend. They save embedding-layer, layer-0, layer-10, final hidden-state, and pooled outputs. The comparison reports numerical drift and retrieval-neighbor agreement.
4. Publish only after the parity gate passes; [`publish_yat_torch_from_gcp.py`](../scripts/publish_yat_torch_from_gcp.py) checks conversion hashes and parity, uploads directly from GCP, verifies the remote weight SHA-256, and removes the temporary token file.

The 2026-09-29 physical TPU result on eight 128-token multilingual/code-like inputs was: pooled minimum vector cosine **0.999850**, maximum pairwise cosine-score drift **0.00503**, top-1 agreement **8/8**, and top-3 set agreement **8/8**. The full result is in the PyTorch release's `parity.json`. This is a small numerical-equivalence check. It is not a production retrieval benchmark, a code-search evaluation, or bitwise parity. The current PyTorch implementation computes dense direct BF16 distances to keep a fixed-shape TPU graph; optimize this path against the JAX reference before high-throughput serving.
