# Independent retrieval, bitext and code development gates

`--retrieval-dev NAME=DIR` now admits a separately prepared development directory into the shared stage admission and physical embedding trainer. This interface does not fabricate training rows or tune against final benchmark test splits. Candidate export remains only a proposal: existing MIRACL/CodeSearchNet rows may already have been used by the parent and therefore fail independent admission.

Prepare one task per gate with [prepare_embedding_retrieval_dev.py](../scripts/prepare_embedding_retrieval_dev.py). It takes an authenticated candidate directory from `prepare_representation_development`, repeated `--source-name` keys from its exclusion receipt, `--exposure-input`, the actual parent file-hash inventory via `--parent-manifest`, matching `--tokenizer`/`--encoder-config`, and a fresh `--output`. Query/document lengths default128/256 and must fit the actual parent. All work here is raw-data/tokenization/metadata work; no model or network calls occur.

The exposure input format is `flaxchat-known-contrastive-exposure-input-v1`:

- `parent_files_sha256`: the actual current parent's weights/config/tokenizer hashes.
- `expected_stage_identities`: nonempty unique SHA256 hashes of the actual historical checkpoint-metadata files in the declared known contrastive inventory.
- `known_contrastive_inventory_complete: true`: an explicit declaration about that inventory, **not proof that undisclosed prior stages do not exist**.
- `stages`: one entry for every expected identity, containing `stage_identity_sha256`, `checkpoint_metadata` and `sources`; each source entry has `name` and `directory` pointing to its real historical prepared data.

Each historical metadata file must contain `resolved_config.data_manifests`. Its complete source inventory must match the supplied sources. The tool authenticates those manifests and their entire train JSONL hashes/counts, then checks the real rows against reserved candidate exact-text and aligned-group identities. A positive overlap, missing metadata/source or incomplete row coverage rejects preparation. It never replaces missing historical data with fake clean fixtures. References are resolved against the original input location and sealed as absolute paths before copying, so actual historical inputs must also remain available to subsequent admission.

[embedding_dev_exposure.py](../flaxchat/embedding_dev_exposure.py) recomputes this evidence at admission. A copied JSON boolean or forged checked-row count cannot substitute for actual authenticated historical files. Completeness is deliberately limited to the declared known-stage inventory; inherited MLM/pretraining, semantic/near-duplicate/translation exposure and completeness of undisclosed contrastive lineage remain explicitly unresolved. If the actual parent lineage is available, include every known stage rather than declaring a convenient subset. Missing history is a reporting limitation, never an unseen-to-parent claim.

The prepared `flaxchat-embedding-retrieval-dev-v1` manifest binds candidate/spec/raw exclusion identities, exact selected candidate source metadata, task, parent hashes, exposure proof/hash, vocabulary/padding/truncation and every loaded raw/token/ID artifact. It contains paired query/positive arrays plus query/document/group identities and languages, with no placeholder training set. The loader recomputes query/group equivalence closure and tokenization from the copied authenticated tokenizer; updating a checksum cannot conceal raw/token disagreement. Selected raw rows must equal authenticated candidate rows in declared order. Duplicate source inventories, substituted tasks, test-split candidates, wrong parent/tokenizer, all-padding/out-of-vocabulary arrays and changed artifacts fail.

Every actual current training source must have `manifest.development_quarantine.identity` equal to the candidate identity. Shared admission authenticates the actual loaded training arrays; independent admission additionally rechecks whole train raw rows against exact/aligned exclusions. An old `parent_exposure_checked` boolean cannot waive this. The existing candidate quarantine helper supplies the identity and matching policy; no alternate normalizer is introduced.

The trainer measures aggregate and per-language retrieval MRR/Recall on TPU-produced embeddings under `independent/NAME` keys. Bitext uses its genuine aligned pairs and language identities; code preserves case, indentation and literals. These gates enter immutable stage identity and baseline/best/recovery quality state alongside existing STS and training-source diagnostics. Selection and regression criteria still need a declared product policy before paid continuation.

Verification consists of five model-free tests using injected raw candidate records and a real tokenizer, including a complete preparation→independent loader→shared `prepare_stage` path. Tests reject changed historical raw inputs, forged/incomplete proofs, actual known-parent exposure, current training exposure, token/raw disagreement, task substitution and duplicate source inventories; they also check transitive relevance closure and code case. These fixtures are not actual production data or physical model acceptance. The new independent gate needs real eligible data, authentic historical exposure inputs, and physical baseline/metric/recovery qualification before it can justify continuation or quality claims.

Parent exposure currently checks the full authenticated exclusion bundle, including capped-out reserved groups. This is deliberately conservative: a bundle containing parent-exposed MIRACL/code candidates will fail even if another task's selected pairs appear fresh. Export an eligible task-only candidate specification for that gate rather than waiving the exposure failure or claiming the mixed bundle is clean.

## Physical integration case

The physical trainer inventory now requires `test_real_trainer_resume_pair_triplet_schema_and_best[False-False-independent]`. It prepares real tokenizer arrays from injected two-language candidate rows, binds an authenticated synthetic historical source, and evaluates the actual TPU encoder without overriding the quality metrics. It requires aggregate and both language metrics, preserved independent-data/exposure identity, uninterrupted-versus-resumed model/optimizer/recovery equality, and rejection of mutated independent raw data before model loading.

This new case has been collected and statically reviewed, but has **not run on physical TPU**. It qualifies integration and recovery when it passes, not production-parent cleanliness or real multilingual/code/bitext/STS quality. Its frozen source must include `configs/data/representation-development-v1.json`, the candidate metadata fixture module and their dependencies. The existing historical physical receipt does not include this node.
